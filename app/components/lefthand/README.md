# 左手ポジション図解アセット

Arcoda の学びレッスン／技法解説で使う、左手のポジション図解とポジション移動アニメーション。

弓アセット（`violin-geometry.ts` / `bowing-motions.ts` / `BowingDemo.tsx`）と同じ設計思想・同じインターフェースで作られている。

---

## 設計の核 — d の一元管理

運弓が「h（毛のどの位置が弦に接するか）」の時系列で定義されるのと同様に、
**ポジション移動は「d（シフト量）の時系列」という 1 つの数値で定義される。**

```
指塊・爪・指しわ = translate(-34 + d, -1.69 + d × 0.0497)
手パス・手しわ  = translate(-49 + d, -2.54 + d × 0.0519)
```

> **パーツごとに動きを作り込んではならない。** 破綻の原因になる。

⚠️ y 係数が異なるのは、弦の傾き(0.0497)とネック下縁の傾き(0.0519)が異なるため。
**片方だけ動かすと、掌がネックから浮いて絵が壊れる。**

```tsx
import { LeftHand } from "@/components/lefthand";

<LeftHand position="1st" pattern="open" />   // 開放弦（どの指も押さえていない）
<LeftHand position="3rd" pattern="f1" />

// ミスパターン（親指が 1 つ前のポジションに取り残される＋指の軸が逆傾き）
<LeftHand position="2nd" thumbLagsBehind reverseTilt />
```

### ポジション移動アニメーション

```tsx
import { PositionShiftDemo } from "@/components/lefthand";

<PositionShiftDemo shift="1st-3rd" playing />
<PositionShiftDemo shift="1st-5th-6th" playing />   // 6th は 5th を経由する

// 停止状態（1st・開放弦の静止画として正しく表示される）
<PositionShiftDemo shift="1st-5th" playing={false} />
```

### ミスパターンのアニメーション

```tsx
import { PositionMistakeDemo } from "@/components/lefthand";

<PositionMistakeDemo shift="miss-1st-2nd" />   // 親指が 1st に取り残される
<PositionMistakeDemo shift="miss-1st-3rd" />   // 親指が 2nd までしか進まない
<PositionMistakeDemo shift="miss-1st-4th" />   // 親指が 3rd までしか進まない
```

**5th / 6th のミスは存在しない。** 正しい手が「親指がネック裏」形状のため、
取り残される形が構造的に別物になる。元絵が提供されるまで規則の外挿は禁止。

## ミスパターン（親指が残る・指が逆傾き）

### 構造（元絵から機械抽出）

| | 変換 |
|---|---|
| 指 | 正しい `fingerTransform(d)` ∘ 剪断 `matrix(1,0,-0.42,1,128.1,0)` |
| 手 | 正しい `handTransform(d)` ＋ **専用のミス手パス**（正しい手60点／ミス手70点） |

ミス手パスは「**掌が 68px 引っ込み、親指がさらに (lag − 68) 引っ込む**」形で描かれている。
`lag`（親指の遅れ量）= そのポジションの d − 1つ前のポジションの d。

| ポジション | lag | 親指の行き先 |
|---|---:|---|
| 2nd | 68 | 1st（**一歩も動かない**） |
| 3rd | 102 | 2nd |
| 4th | 102 | 3rd |

### モーションは s（移動進捗 0→1）の一元管理

```
指  = fingerTransform(D·s) ∘ translate(128.1·s, 0) ∘ skewX(-22.78241° · s)
手  = handTransform(D·s + 68·(1 - s))              ← 掌の遅れ
パス = missHandPath(68 - (68 - lag)·s)             ← 親指の追加の遅れ

⇒ 親指の絶対x = 314 + s·(D - lag)   掌の絶対x = 471 + s·(D - 68)
```

**親指・掌ともに単調増加し、最終値を超えない。これが唯一の合格条件**（`assertMonotone()` で検証）。

### ミスパターンの禁則（実際に踏んだ罠）

> ❌ **ミス手を到達位置で静止させ、終盤にクロスフェードしてはならない。**
> 正しい手が親指を前進させたあとにミス手の親指が後ろから現れ、**親指が逆戻りして見える。**

> ❌ **親指の座標だけを s に比例させてはならない。**
> ミス手は掌も 68px 引っ込んでいるため、s=0 のとき掌だけが左に残り、
> **親指の左に出っ張りが生じる。** 掌の遅れも s に比例させること。

> ❌ **transform と `d` 属性で異なる keyTimes / keySplines を使ってはならない。**
> 進捗がずれ、**親指が逆戻りする。**

> ❌ **静止画のミスを「1つ前のポジションの handTransform」で描いてはならない。**
> 掌まで丸ごと後ろに下がる。専用パス（`MissHandShape`）を使うこと。

### なぜ SMIL なのか
親指の遅れは path の `d` の変化として現れる。CSS の `d: path()` は対応環境が限られるため、
**ミスモーションだけ SMIL 駆動**にしてある（正解モーションは CSS のまま）。

### 剪断は matrix のままアニメーションできない
`animateTransform` の `type` は translate / scale / rotate / skewX / skewY のみ。
`matrix(1,0,-0.42,1,128.1,0)` は以下に分解して `additive="sum"` で3本重ねる。

```
matrix(1,0,-0.42,1,128.1,0) ≡ translate(128.1, 0) skewX(-22.78241°)     // tan = -0.420000
```

## モーションのタイムライン（教則設計）

```
開放弦（全指浮き）で静止
  → 1の指を押弦
  → 静止して確認
  → 移動（ease-in-out・途中で止まらない）      ← 教則上の要点
  → 到着して静止（耳で音程を確認する間）
  → 1st へ戻る → 指を離して開放弦へ（シームレスループ）
```

| shift id | 経路 | 持ち替え |
|---|---|:---:|
| `1st-2nd` | 1st → 2nd | – |
| `1st-3rd` | 1st → 3rd | – |
| `1st-4th` | 1st → 4th | – |
| `1st-5th` | 1st → 5th | ✓ |
| `1st-5th-6th` | 1st → 5th → 6th | ✓ |

**5th → 6th では手は動かない。指だけが先へ伸びる**（元絵の 5th と 6th の手パスは同一）。

## ポジション定義

| ポジション | d | 胴オーバーレイ | 親指がネック裏 |
|---|---|:---:|:---:|
| 1st | 0 | – | – |
| 2nd | 68 | – | – |
| 3rd | 170 | ✓ | – |
| 4th | 272 | ✓ | – |
| 5th | 340 | ✓ | ✓ |
| 6th | 391 | ✓ | ✓ |

2nd への移動量 = 指幅 1 本分 = 68px。**それ以降は等間隔ではない**（68 / 102 / 102 / 68 / 51）。
元絵の実測値であり、計算で導いてはならない。

## 指パターン

| id | 内容 |
|---|---|
| `open` | どの指も押さえていない（開放弦） |
| `f1` | 1 の指のみ押弦（他 3 指は浮かせ） |
| `f12` | 1〜2 の指を押弦 |
| `f123` | 1〜3 の指を押弦 |
| `f1234` | 全指押弦 |
| `f1_up2` | 1 押弦・2 を立てる |
| `f12_up3` | 1,2 押弦・3 を立てる |

押弦指と浮かせ指の差は、**爪の短縮遠近（24×16 rx5 → 24×8 rx3）と DIP しわの有無だけ**で表す。
指本体パスの下端は 4 指とも同一（背景に空白を作らないため）。

## 実装上の注意（重要）

### アニメーション時に transform を二重に掛けてはならない
`FingersShape` / `HandShape` は既定で `transform` 属性を出す。
CSS アニメーションが外側の `<g>` に transform を与える場合、**`animated` を渡して内側の
transform を抑止すること**。両方に付くと変換が二重に掛かり、絵が -68px ずれる。

### 胴オーバーレイは常時表示してはならない、が、遅すぎてもならない
- 常時表示すると、1st 位置にある前腕を覆ってしまう（元絵の 1st/2nd に胴オーバーレイはない）。
- 逆に、**ネック裏の手形が現れるより前に不透明化しきっていないと、掌が胴から透ける。**
- `overlayOpacityKeyframes()` は移動開始直後の 3% で不透明化を完了させる。

### 持ち替え（親指がネック裏へ回る）は移動の終盤で行う
往路は移動距離の 72〜100%、復路は 0〜28% の区間。
早すぎると、4th の位置を通過する時点で正しい手形が消えてしまう。

### 指の傾きを反転させるとき、鏡映は禁止
`scale(-1,1)` を使うと**指の並び順まで反転**し、人差し指が右端に来てしまう。
指先ライン(y=305)を固定した剪断を使うこと: `matrix(1,0,-0.42,1,128.1,0)`

### 前腕を回転させてはならない
手ごと回転させると指と掌が分断される。前腕の角度（45°）はパス自体に焼き込まれている。

### 手パスの `L 458,371` 以降を削ってはならない
この区間（掌上縁 → 水かきの窪み → 親指の内縁）が、掌上縁とネック下縁の「一本線」を成立させている。

### 描画順は 指塊 → 指しわ → 爪
爪が最前面。順序を入れ替えると爪の輪郭がしわに削られる。

## 不変条件（改変したら必ず確認）

1. **掌上縁とネック下縁の「一本線」**: 掌の上端が `y = 365 + (x - 345) × 0.0519` に載る（残差 ≤3px）
2. 指先が弦の上に着地している
3. 浮かせ指の直下に背景の空白がない
4. 手が単一の連結成分（分断していない）

### 既知の「欠陥ではない」検出
- ナット部: 15px ／ 水かき: 139〜151px ／ ミスパターンの水かき: 233〜312px

## 検証記録

| 検証項目 | 結果 |
|---|---|
| TSデータから静止画を生成 → 確定SVGと画素比較（1st〜6th × f1） | ✓ **差分 0** |
| ミス静止画（2nd / 4th × `thumbLagsBehind reverseTilt`）→ 確定ミスSVGと画素比較 | ✓ **差分 0** |
| ミスモーションの親指・掌の単調性（2nd / 3rd / 4th） | ✓ 単調増加・行き過ぎなし |
| 同（1st × f12 / f123 / f1234） | ✓ **差分 0** |
| 同（1st × open ＝ 承認済みの全指開放） | ✓ **差分 0** |
| `f1_up2` / `f12_up3` | ⚠ 出典SVG未提供・未照合 |

### 検証方法
1. **XML 検証**: 構文チェック（文字列置換の事故が多い）
2. **ピクセル逆測定**: 軸角は縁の直線回帰／弧は矢高／切れ目はフラッドフィル
3. **実地再現テスト**: TSデータから SVG を組み立て → レンダリング → 確定SVGと差分ゼロを確認
