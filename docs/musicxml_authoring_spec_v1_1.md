# MusicXMLスコア作成マニュアル v1.1（外注先向け）

作成日: 2026-07-26 / 発注元: Arcoda / 改訂: v1.1

> v1.0 からの主な変更（発注元による実装突き合わせの結果）
> - 記号は「見た目」ではなく **標準MusicXML要素として入力**することを明確化（§5 冒頭・付録A）。当アプリは記号を要素パスで機械的に読むため、テキストや装飾で似せても無効。
> - ファイル形式ルールの根拠を明記（§1）。**プレーンXMLであること**を検収で先頭バイトから機械判定する。
> - タイトル・作曲者などのメタ情報は**ファイルに入れなくてよい**ことを明記（§1）。アプリは読まない。
> - pizz. / スピッカート等、記譜ソフトの書き出し形式が要検証の項目に印を付けた（§5-3・§7）。**サンプル検証（§10）で確定**する。

---

## 1. 目的と成果物

原本PDF楽譜をもとに、記譜ソフト **Notion Mobile**（PreSonus社・無料）でスコアを入力し、**非圧縮 MusicXMLファイル（.musicxml）** として納品していただきます。

- 対象は **バイオリンパートのみ**（伴奏パートは入力不要）
- 反復記号（リピート、D.C.、D.S.等）は **原譜通りに記譜**（展開しない）。※展開はアプリ側が自動で行います
- 目的は「見た目の再現」ではなく「**楽譜情報の欠落なきデータ化**」です。レイアウト（改行・余白・フォント）は一切不要
- **タイトル・作曲者・難易度などのメタ情報はファイルに入れなくて構いません**（アプリは読み取らず、発注側が別途登録します）。ファイル名だけが識別子です

### 納品物
| 項目 | 内容 |
|---|---|
| ファイル形式 | **非圧縮 .musicxml**（.mxl 不可） |
| ファイル名 | `曲名ローマ字_作曲者ローマ字_v1.musicxml`（例: `gavotte_gossec_v1.musicxml`） |
| 添付 | 申し送り表（§7。該当事項がある場合のみ） |

> **なぜ非圧縮か**：圧縮版（.mxl）は中身がZIPで、検収時の内容確認・差分チェックができません。過去に「拡張子は .musicxml なのに中身がZIP」という納品事故があったため、**先頭が `<?xml` で始まるプレーンなテキストXML**であることを検収で機械確認します。エクスポート時は必ず「MusicXMLファイル（非圧縮）」を選んでください。

---

## 2. 環境準備

1. お使いの端末のアプリストアで「**Notion Music**」を検索し、Notion Mobileをインストール（iOS / Android / Windows / macOS すべて対応）
2. **課金・アカウント登録は不要**です（MusicXMLエクスポートは無料版の標準機能）
3. 推奨環境: タブレットまたはPC＋物理キーボード。キーボードショートカットで入力効率が大きく向上します

---

## 3. 新規スコア作成

1. スタートページの「+」をタップ
2. ファイル名に曲名を入力（§1の命名規則）
3. ［インストゥルメントを選択］→ Strings → **Violin (solo)** を選択 →［追加］→［OK］
4. 調号・拍子・テンポを原譜通りに設定（ツール: 調号 = K、拍子記号 = M、テンポ = J）

**⚠ 調号は最重要項目です。** アプリは記譜された調号を音高解析より優先して信頼します。調号の入力漏れ・誤りは、音程解析そのものを狂わせるため **検収で即差し戻し** です。「臨時記号だらけで調号なし」は不可。短調の曲は短調の調号（＝並行長調と同じ♯♭数）で正しく設定してください。

---

## 4. 入力方法

**ステップ入力を標準とします。**

- ツールパレットの音符ツールでデュレーション選択 → 画面上ピアノ鍵盤または接続MIDIキーボードで音高入力
- タイはタイツール（ショートカット T）
- 休符は休符アイコンまたはスペースキー

### 禁止する入力方法
| 方法 | 理由 |
|---|---|
| リアルタイム録音 | クオンタイズ誤差により音価・リズムが原譜とずれるため |
| 手書き入力 | 認識誤りが混入しやすく、既存要素が破棄される場合があるため |

---

## 5. 必須入力要素チェックリスト

以下は原譜にある限り **すべて入力必須** です。1つでも欠落があると再生・解析データとして成立しません。

> **★最重要の原則：記号は「専用の入力機能」で入れる。**
> アプリは各記号を **標準MusicXMLの要素**として機械的に読み取ります（例：スタッカートは `<staccato>` 要素、スラーは slur 要素、重音は `<chord>` 要素）。
> **見た目をテキストや図形で似せても、データとしては存在しないものと扱われ、解析に反映されません。**
> 必ず Notion の正式なアーティキュレーション／装飾／スラー等の機能を使って入力してください。判断に迷う記号は勝手に代用せず §7 で申し送りを。

### 5-1. 基本
- [ ] 調号（曲中の転調含む）
- [ ] 拍子記号（曲中の変更含む）
- [ ] テンポ記号・メトロノームマーク
- [ ] 全音符・休符（音高、音価、付点、**連符**）※連符は必ず正式な連符機能で（音価の見た目合わせは不可。アプリは連符マークを正本にリズム判定します）
- [ ] タイ
- [ ] 弱起小節（原譜が弱起なら弱起小節として設定。コンテキストメニュー > 小節 > 弱起小節）

### 5-2. 反復・進行
- [ ] 反復線（リピート開始・終了、1番/2番括弧）
- [ ] D.C. / D.S. / Coda / Fine 等のナビゲーション記号

**⚠ ナビゲーション記号は入力順序が重要です。** Notionでは以下の順序で正しく入力しないと再生（およびアプリ側の自動展開）が破綻します。
- Segno → Fine → D.S. al Fine
- Segno → To Coda → D.S. al Coda → Coda

入力後は必ず全曲再生し、原譜通りの順序で進行することを確認してください。

### 5-3. アーティキュレーション・奏法
- [ ] スラー
- [ ] スタッカート、アクセント、テヌート
- [ ] スタッカート系の細分：**スタッカート／スピッカート／ポルタート（detached legato）を区別**して入力〔※要検証・§10〕
- [ ] 強弱記号（p, f, cresc., dim., ヘアピン等）
- [ ] トリル、モルデント等の装飾記号
- [ ] 装飾音符（前打音等）
- [ ] トレモロ
- [ ] グリッサンド／ポルタメント
- [ ] pizz. / arco（ショートカット Shift+Z）〔※pizz.の書き出し形式は要検証・§10〕
- [ ] ハーモニクス記号
- [ ] 重音（和音）— 構成音をすべて入力（**必ず和音として。単音を並べない**）
- [ ] 運指番号（**原譜に記載がある場合のみ**。ショートカット W）
- [ ] 弦指定（sul G 等、原譜にある場合）

> 〔※要検証〕印の項目は、記譜ソフトごとに書き出しのされ方が違う可能性があります。**まずは原譜通り正式機能で入力**してください。§10のサンプル検証で書き出し形式を確定し、必要なら本マニュアルを更新します。判別が難しい場合は §7 で申し送りを。

### 5-4. 入力不要なもの
- ページレイアウト、改行位置、段組
- タイトル／作曲者などのファイル内メタ情報（アプリは読みません。入れても害はありません）
- リハーサル用の練習番号（原譜にあれば入力推奨だが必須ではない）
- 出版社の校訂注・脚注テキスト

---

## 6. 禁止事項

1. **タチェット設定を使わない**（音符が再生されない状態で納品しない）
2. **音を「修正」しない** — 原譜が誤植と思われる場合も勝手に直さず、原譜通り入力し申し送り表に記載
3. 移調モードを変更しない（コンサートピッチのまま）
4. 声部を不必要に分割しない — 単旋律は声部1のみ。重音は和音として入力し、原譜が明確に2声で書かれている場合のみ声部2を使用
5. 原譜にない記号を追加しない
6. 記号を図形・テキスト・装飾で「見た目だけ」再現しない（§5冒頭の原則）

---

## 7. 申し送り表

以下に該当する場合、納品時にテキストで報告してください。

| 状況 | 記載内容 |
|---|---|
| Notionで入力できない記号があった | 小節番号＋記号の内容 |
| 原譜の誤植疑い | 小節番号＋疑いの内容＋入力した通りの内容 |
| スタッカート系で判別困難（スタッカート／スピッカート／ポルタートの区別が不明瞭） | 小節番号のみで可 |
| pizz. / arco の切替がある | 小節番号（書き出し形式の検証に使います） |
| ハーモニクス・トレモロ・グリッサンド等、入力方法に迷った | 小節番号＋記号＋どう入力したか |
| その他判断に迷った箇所 | 小節番号＋判断内容 |

## 8. セルフ検証手順（納品前必須）

1. **小節数照合**: 入力スコアの総小節数が原譜と一致すること
2. **全曲再生**: 原譜を目で追いながら最後まで再生し、音高・リズム・反復進行を確認
3. **エクスポート**: アプリケーションメニュー > ［スコアをエクスポート］> ［ファイルを保存］> **MusicXMLファイル（非圧縮）** を選択
4. **再読込確認**: エクスポートした .musicxml をNotionで開き直し、正常に表示・再生されること
5. ファイル名が命名規則に従っていること
6. ファイルを**テキストエディタで開き、先頭が `<?xml` で始まる**こと（`PK` で始まる場合は圧縮＝差し戻し対象）

---

## 9. 検収基準（発注側）

以下を自動・手動で確認します。不合格の場合は該当箇所を明示して差し戻します。

- ファイルが**プレーンなMusicXML**であること（先頭バイトが `<?xml`／ZIP=`PK` でない）
- MusicXMLとしてパース可能であること
- **調号（key/fifths）が正しく含まれていること**（音程解析の土台。ここが最優先）
- 小節数・音符数が原譜と一致すること
- §5チェックリスト項目の欠落がないこと（アーティキュレーション・スラー・重音・連符・タイ等が**標準要素として存在**するか）
- 申し送り表と実データの整合

---

## 10. サンプル検証について（発注前の1回のみ）

本マニュアル確定のため、最初に **§5-3の全記号を1曲に詰め込んだ短いテストスコア** を1本だけ作成・書き出していただきます。発注側でその実データを解析し、各記号がアプリの期待する形式で書き出されているか（特に pizz. / スピッカート / ポルタート / トレモロ / ハーモニクス）を確認します。結果に応じて本マニュアルへ「この記号はこう入力する」を追記して確定版とします。本番発注はその後です。

---

## 付録A：アプリが各記号から何を読み取るか（なぜ正式入力が必要か）

契約者の理解を助けるための参考情報です。アプリは記号を以下の用途に使います。**要素が無い＝その練習機能が働かない**、という関係です。

| 入力する記号 | アプリが自動で行うこと |
|---|---|
| 調号 | 音程の正誤判定の基準。全体の解析精度を左右 |
| 拍子・テンポ・音価・連符・タイ | リズム／タイミングの採点、テンポガイド生成 |
| 反復・ナビ記号 | 演奏順の自動展開（曲を通しで解析） |
| スラー／スタッカート／スピッカート／ポルタート | 弓の奏法課題の自動タグ付け・採点対象の抽出 |
| トリル／モルデント／装飾音 | 装飾技法の技術タグ付与 |
| トレモロ／ハーモニクス／pizz. | 各特殊奏法の検出・専用評価 |
| 重音（和音） | 重音課題の検出・構成音の評価 |
| 運指・弦指定 | ポジション表示・運指ガイド（無い場合はアプリが推定） |
| 強弱記号 | 記号ガイド表示 |
