# 弦ちがいの教材を作る指示書 v35

バイオリン教材の MusicXML を、別の弦で弾く版に作り替えるための指示書。

## 0. 仕事の形

### 0-1. 言葉の決め

| 言葉 | 意味 | 例 |
|---|---|---|
| **元の版** | 変換のもとにする、1本の弦用に書かれた MusicXML。「原譜」「元の譜面」とも言わず、この語で統一する | `1-3-5-7ポジション移動_A線_③.musicxml` |
| **系統名** | ファイル名の先頭トークン。教材グループの単位 | `1-3-5-7ポジション移動` |
| **組** | ファイル名から**弦のトークンだけを伏せた残りが一致する**まとまり。最大4本。いま素材には3本や2本しか無い組もある | `1-3-5-7ポジション移動_{弦}_③` の4本 ・ `1指のポジション移動_{弦}` の4本 |
| **素材フォルダ** | 元の版が置いてある場所。**作る側は書き込まない。**人だけが §0-3・§4-5・§9-1 の6・7・8・§9-2 の9 で書く | 既定は `C:\Users\tetsu\OneDrive\Desktop\アルコ用教材\ポジション移動`。登録スクリプトの `SRC_DIR` で変えられる |
| **出力置き場** | 作ったものを置く別のフォルダ | |
| **検収フォルダ** | 元の版と出力を2本だけ並べた、突き合わせ用のフォルダ | |
| **族カード** | 練習メニューの一覧に出る、教材グループ1つぶんのカード。押すと練習前シートが開く | |

**同じ「系統」という語が、2つの画面で別のものを指す。** 照合スクリプト（`check_string_variants.py`）の「系統」はこの指示書の**組**。登録スクリプト（`upload_position_shift.ts`）の「系統」はこの指示書の**系統名**で、教材グループと同じ。

### 0-2. 渡すもの・作るもの

**渡すもの**
1. 元の版 1つ（平文XML）
2. 目標の弦
3. 素材フォルダ**直下**の `.musicxml` と `.mscz` のファイル名一覧（**名前の重複を見るためだけに使う。`.mscz` を変換元として開いてはいけない**）。サブフォルダは含めない。`古い/` に退避したものは数えない

**作るもの**: 目標の弦の MusicXML 1つと報告。または「作らない」という報告だけ。

**決め**
- 1回につき**1本だけ**作る。複数まとめて渡されても1本ずつ独立に処理する
- **同じ名前のファイルが `.musicxml` でも `.mscz` でも存在するなら作らない**（§5-22）
- 出力は**出力置き場**に書く。素材フォルダには絶対に書かない
- 変換元として開いてよいのは、渡された元の版1つだけ
- §5 の中止条件に1つでも当たったら、**MusicXML を出さず理由だけを報告する**。推測で補ったり直したりしない
- **完成の定義**: ひとつの**組**が、4本そろっている状態。ただし `作れない弦.md`（§9-1 の8）に書いた弦は数に入れない

### 0-3. 始める前に人がやること

**素材の `<instrument-name>` を `Violin` にする。** 日本語の `ヴァイオリン` のままだと、採点のピッチ検出の上限が既定の E6（MIDI 88）に落ち、それを超える音は「検出できない」ではなく**別の高さとして採点され続ける**。`Violin` なら G3〜E7（MIDI 100）まで見る。

**始める前に、素材フォルダ全体へ照合スクリプトを一度当てる。**

```
python scripts/check_string_variants.py "<素材フォルダ>" --base G --json baseline.json
```

画面に `=== 先に直す元の版 ===` の節が出たら、そこに並ぶ元の版を**先に直す**。スクリプトが §9-1 の3 の**仕分け(2)**（§5-1〜16・「ファイルを読めない」・「音符が1つも無い」）だけを選んで出す。終了コードもそれだけで決まる。
全角の運指・BOM・臨時記号の欠落（仕分け(3)）は `[組名]` の下に参考情報として出る。ここで出ても作り始めてよい。出力側で直すか、別途人が直す。
**楽器名を直す前に回すと「採点できる高さの上限(88)を超える音」が36件出る。**これは上の第1段（`<instrument-name>` を `Violin` にする）を済ませれば消える。先に第1段をやってから下見を回すほうがよい。
**`(基準 …)` の行は読み飛ばさない。** ここには既存の4弦どうしを突き合わせた結果が出る。実素材では**15本が組の G線版と食い違っている**。調号が5度の連鎖から外れているもの、音が全部ずれているもの、異名同音で書かれているものが混ざっている。

これが効くのは、**検収が「出力とその元の版」しか見ない**からである。食い違っている版を元の版に選ぶと、そこから作った出力は検収を通り、組は4本そろって完成の定義を満たす。**中身は他の3弦と別物のまま**になる。

だから下見の段階で、`(基準 …)` の行が出た組については**どの版が正しいかを人が決める**。正しくないほうは直してから使う。**登録済みなら §9-1 の6 の手順（`REPLACE=1`）、未登録なら直した素材を §9-2 の9 でそのまま登録する。**直すまで元の版に選ばない。

`--base` には**全部の組にある弦**を渡すのが基本。実素材では `G`。基準の弦が無い組については、スクリプトが**その組にある一番低い弦を代理の基準にして必ず突き合わせる**（`基準の◯線が無いので◯線を代理の基準にした` と出る）ので、どの弦を渡しても取りこぼしは出ない。下の「15本」は `--base G` で回したときの数。

いま分かっている仕分け(2)の元の版は次の3本。

- **`2-4-6-8ポジション移動_A線_①`**: `<string>` が1つも無く、運指だけ（§5-8）
- **`1指のポジション移動_G線`**: 第4小節1拍目の A3 に `<fingering>` が無い（§5-8）。組の基準にする弦なので、この素材からは他の3弦を作れない
- **`4指のポジション移動_E線`**: `<string>1`（E線）のまま B4〜E5 が8音入っている。7音は開放E（MIDI 76）より低く、1音は 76 ちょうどで指番号4（§5-9・§5-10・§5-11）。E線で B4 は物理的に押さえられない

`2-4-6-8ポジション移動_A線_①` について補足すると、このまま元の版として渡すと §5-8 で必ず中止になる。MuseScore で弦番号を入れてから使う。登録済みの教材は登録スクリプトがファイル名の弦で `<string>` を書き足してから上げるので、**DB を見ても健全に見え、素材だけが欠けている**という気づきにくい形になっている。この書き足しは登録側だけの救済で、**この指示書では使わない**。作る側は §5-8 で中止する。

これをしないと、**E線版は作れる組すべてが §5-20 で中止**になる。素材120本はすべて日本語名で、E線に移すと最高音が 89〜99 に達するため。**E線だけの話ではない。**素材には A線の時点で 88 を超える版が7本あり（`3-4-5-6-7-8-9-10ポジション移動_A線_①②`・`3-5-7-9ポジション移動_A線_①②③`・`3指のポジション移動_A線`・`4指のポジション移動_A線`）、その組では G線・D線から A線版を作るときも中止する。**88 を超える素材は全部で36本ある。A線7本・E線29本。**この36本のうち既に登録されているものは、素材を直したうえで `REPLACE=1 ONLY=…`（§9-1 の6 のコマンド）で上げ直す。退避も作り直しも要らない。直すのは1要素だけなので。登録されていなければ、直した素材をそのまま §9-2 の9 で登録する。
**上げ直さないかぎり、その教材は 88 を超える音を別の高さとして採点し続ける。**これから作る話ではなく、いま起きている話。素材のファイルを直しただけでは Storage の写しが `ヴァイオリン` のまま残り、その教材の採点の上限が E6 に取り残される。直すのは `<instrument-name>` の1要素だけで、`<part-name>` と `<instrument-sound>` は既に正しい。§7 でメタデータの変更を禁じているので、**作る側では直せない**。

## 1. 弦とポジションの決め

| 言葉 | 意味 | 値 |
|---|---|---|
| **MusicXML弦番号** | `<string>` に書く数字 | E線=1・A線=2・D線=3・G線=4 |
| **弦インデックス** | 低い弦から数えた位置 | G線=0・D線=1・A線=2・E線=3 |

- となり合う弦は **完全5度 = 7半音 = 音名4文字ぶん**
- 開放弦: G線=G3(MIDI 55)・D線=D4(62)・A線=A4(69)・E線=E5(76)
- **音名番号** = オクターブ × 7 + 文字番号（C=0・D=1・E=2・F=3・G=4・A=5・B=6）。例: A4 → 4×7+5 = 33。♯♭は文字を変えないので音名番号に影響しない
- **ポジション**（解析器と同じ数え方。半音ではなく文字数で数える）:

  ```
  その音の MIDI が開放弦の MIDI 以下 → 未定義（その弦では鳴らない。いちばん先に見る）
  指番号 0（開放弦）→ 未定義
  pos = (その音の音名番号 − (指番号 − 1)) − 開放弦の音名番号
  pos == 0 かつ 指番号 == 1 → pos = 1 （ハーフポジションは1stへ繰り上げ）
  pos < 1 または pos > 14 → 未定義
  ```

**この指示書の目的は、指づかいとポジションを1音も変えずに、弦だけを移すこと。**

## 2. 弦の距離 n

```
n = 目標弦の弦インデックス − 元の弦の弦インデックス
```

n は負にもなる。例: G線→A線 は n = +2、E線→D線 は **n = −2**、E線→A線 は n = −1。
以降のすべての式は n の符号をそのまま使う。

## 3. 音の高さを動かす

`<pitch>` を持つ音符それぞれについて、次を**同時に**満たす値へ書き換える。

```
新しい音名番号   = 元の音名番号 + 4 × n
新しいオクターブ = 新しい音名番号 ÷ 7 の商   （商は小さくなる向きに切り捨て。負でも同じ）
新しい文字       = 新しい音名番号 ÷ 7 の余り （余りは常に 0〜6。0=C 1=D 2=E 3=F 4=G 5=A 6=B）
新しい MIDI      = 元の MIDI + 7 × n
新しい alter     = 新しい MIDI − 新しい文字・オクターブの♯♭なしの MIDI
```

- **異名同音に書き替えてはいけない。** 高さが合っていても文字が違えばポジション判定が1つずれる。実例: G♯5 は音名番号39でE線第2ポジション、A♭5 は40で第3ポジション
- 新しい alter が **±2 の外**になったら中止する
- `<pitch>` は**記譜音**で、実音は `<transpose>` のぶんずれる。バイオリンは移調楽器ではないので `<transpose>` は無いか恒等で、そのとき `<pitch>` = 実音になる。0 でない `<transpose>` を持つ譜面は中止（§5-5）。オッターヴァ記号は実音に影響しない

### 3-1. 表示する臨時記号
`<accidental>` は**元の音符に書かれていたかどうかをそのまま引き継ぐ**。記号の種類だけ新しい alter に合わせる。`cautionary` や `parentheses` の属性はそのまま残す。

| alter | 書く記号 |
|---|---|
| +2 | double-sharp |
| +1 | sharp |
| 0 | natural |
| −1 | flat |
| −2 | flat-flat |

元に `<accidental>` が無ければ、新しい音符にも付けない。

## 4. 弦・運指・調号

### 4-1. 弦と運指は必ず対で扱う
アプリは `<string>` と `<fingering>` が**両方そろっている音だけ**、楽譜の指定を「注釈どおり」として最優先で読む。片方しか無い音は「推定」に落ちる。

- **運指だけがある音**: 弦は書かれていないので、音高と指から解き直される。直前の音との流れで決まり、手がかりが無ければ「1stポジションで鳴らせるならそちら・同じなら高い弦」に倒れる
- **弦だけがある音**: 弦は採用されるが、指が無いのでポジションは指なしで導かれ、扱いは推定のまま

どちらも注釈の確度が落ちるので、**必ず対で書く**。

さらに、**弦と運指は同じ `<technical>` の中に入れる**（§5-16）。アプリは1つの音符の**最初の `<technical>` しか読まない**ので、`<notations>` を2つに分けて弦と運指を別々に置くと、両方あるのに「そろっていない」と判定される。

- `<pitch>` を持つ音符の `<string>` を、目標弦の MusicXML弦番号に置き換える
- **元の版に `<string>` か `<fingering>` のどちらかが無い音があれば、書き足さずに中止する**（§5-8）
- **休符（`<rest>`）には `<technical>` を付けない**
- 1つの音符に、中身のある `<fingering>` は**ちょうど1つ**。空の `<fingering></fingering>` は**位置にかかわらずすべて削除する**。読み取り経路のひとつは最初の要素しか見ないので、空タグがあるとその音は運指なし扱いになる。削除したことは報告に書く

### 4-2. 運指の値
`<fingering>` の数字は**1音も変えない**。全角数字（`２` など）があれば半角に直す。数字に対する書き換えはこれだけ（空タグの削除は §4-1）。

- 指番号 0 は開放弦。弦が変わると鳴る音も変わるが、0 のまま引き継ぐ

### 4-3. 調号
`<key>` の `<fifths>` を `fifths + n` にする。`<key>` が複数あっても値はすべて同じはず（違えば §5-6 で中止）なので、全部を等しく動かす。

- `<mode>` は元にあれば**そのまま引き継ぐ**。無ければ足さない
- `<fifths>` を持つ `<key>` が1つも無い譜面は中止（§5-6）

### 4-4. 使ってよい調号の範囲

**表 4-4a（中止の判定に使うのはこちら）**

| 調性 | 作ってよい fifths |
|---|---|
| 長調 | **−6 〜 +7** |
| 短調 | **−7 〜 +4** |

**`<mode>` が書かれていない譜面は長調の行を使う。** 登録側が mode 無しを無条件に長調として読むため。譜面を見て短調だと判断しても、短調の行を当ててはいけない。

この範囲は五線の都合ではなく、**登録時に調の名前を出す表の都合**。範囲の外では、譜面が合っていても DB に入る調名が異名同音に寄る（長調 −7 は C♭ でなく B、短調 +5/+6/+7 は G♯m/D♯m/A♯m でなく A♭m/E♭m/B♭m）。調名は解析でも直されないので、食い違ったまま公開される。

異名同音で逃げてはいけない。実例: `2-4-6ポジション移動_{弦}_②` と `_④` の E線版は8つ目の♯を避けて A♭長調で書かれ、ポジションが 2nd/4th/6th ではなく **3rd/5th/7th** と判定され、教材名と中身が食い違ったまま本番に入っている。

**表 4-4b（元の版を作る人への目安。判定には使わない）** 4弦すべてを作れるようにするなら、元の版の fifths をこの幅に収めておく。1本だけ作るときの合否は 4-4a で決まる。

| 元の版の弦 | 長調なら fifths | 短調なら fifths |
|---|---|---|
| G線 | −6 〜 +4 | −7 〜 +1 |
| D線 | −5 〜 +5 | −6 〜 +2 |
| A線 | −4 〜 +6 | −5 〜 +3 |
| E線 | −3 〜 +7 | −4 〜 +4 |

### 4-5. 範囲を外れたとき、元の版をどう直すか

報告には「元の版の調を選び直せば4弦とも作れる」と書き、fifths がいくつなら収まるかを示す。**直すのは元の版を直す人で、この指示書の仕事ではない。** 直し方は2つあり、性質が違う。

| やり方 | 音名の文字 | 実音 | ポジション番号 | 指と指の間隔 |
|---|---|---|---|---|
| **A. 移調する** | 変わる | 変わる | **変わる** | 保たれる |
| **B. 調号だけ差し替え、失う♯♭を臨時記号で書く** | 保たれる | **保たれる** | 保たれる | 保たれる |

**B にも代償がある。** 登録側は最初の `<fifths>` だけを見て調名を決めるので、`2-4-6ポジション移動_G線_②` を fifths=5 から 4 に下げると、鳴る音は B 長調のままなのに **DB には E 長調として入る**。4弦とも同じだけずれるので §9-2 の10 の突き合わせでは見つからない。おすすめ練習の調フィルタも、この名前で効く。承認するときは、先生が音程の型を見るだけでなく、**この調名のずれを受け入れるかも決める**。

- **A は使わない。** ポジション番号が動き、`2-4-6ポジション移動` が `1-3-5` や `5-7-9` に化ける。§4-4 が悪例として挙げているのと同じ食い違いになる
- **B が正しい。** 例: `2-4-6ポジション移動_G線_②` は fifths=5 なので E線版に 8 が要って作れない。fifths=4 に下げ、失う A♯ を臨時記号で書けば、実音も指の間隔もポジションも元のままで、G:4 D:5 A:6 E:7 と4弦すべて収まる
- **調号だけ下げて臨時記号を書かないのは B ではない。** その文字の実音が半音下がり、指と指の間隔が変わる。ポジション番号が同じでも、音程の型という教材の眼目が別物になる。書き直した元の版は、**先生が音程の型を見て承認してから**使う

## 5. 中止する条件

どれか1つでも当たったら、MusicXML を出さず理由を報告する。

**入力そのものの不備**
1. `<part>` が2つ以上ある
2. `<staves>` が2以上、または `<staff>` が2種類以上
3. `<backup>` がある、または `<voice>` が2種類以上
4. `<chord>` がある（重音は1本の弦では弾けない）
5. `<transpose>` の `<chromatic>` または `<diatonic>` が 0 でない（移調楽器の譜面。`<pitch>` が実音でない）
6. `<fifths>` を持つ `<key>` が無い、または `<fifths>` が2種類以上ある
7. 元の `<string>` が2種類以上ある、またはファイル名の弦と食い違う
8. `<pitch>` を持つ音符に `<string>` か `<fingering>` が無いものがある
9. 元の版に、元の弦の開放弦より低い音がある
10. 元の版に、開放弦と同じ高さなのに指番号が1以上の音がある
11. 元の版に、ポジションが 1〜14 に収まらない音がある（指番号 0 を除く）
12. 元の fifths が表 4-4a の範囲の外
13. `<fingering>` の値が、半角に直しても 0〜4 の整数にならない音がある
14. 指番号 0 なのに、その音の高さが元の弦の開放弦と違う音がある
15. 1つの音符に中身のある `<fingering>` が2つ以上ある、または休符に `<technical>` が付いている
16. 弦と運指が別の `<technical>` に分かれている音がある

**変換した結果の不備**
17. 変換後の fifths が表 4-4a の範囲の外
18. 新しい alter が ±2 の外
19. 目標弦の開放弦より低い音ができる（9 を通っていれば起きない。二重の保険）
20. 変換後の最高音が **MIDI 88 を超える**のに、`<instrument-name>` が `Violin` でない（§0-3 をやっていれば起きない）
21. 変換後の最高音が **MIDI 100 を超える**。`Violin` と書いても採点のピッチ検出はここが上限

**運用上の不備**
22. 出力するファイル名が、素材フォルダに `.musicxml` または `.mscz` として既に存在する
23. ファイル名の弦トークンが1つに定まらない（§6）

## 6. ファイル名

- 教材名 = ファイル名から**いちばん後ろの `.` 以降（拡張子）だけを取り除いた文字列**。これがそのままアプリ上の教材名になる
- ファイル名は `_` で区切られたトークンの並びとみなす。アプリの規約は **`系統名_軸1_軸2`**。先頭が系統名、2つ目以降は練習前シートで選ぶ軸の**値**になる
  - 選択肢そのものは教材グループの `axes` に保存された配列で、ファイル名からは作られない。**新しい弦を足したら軸を作り直さないと、その弦はシートに現れず到達できない**（§9-2 の9）
- トークンのうち **`G線` `D線` `A線` `E線` のどれかに完全一致するものがちょうど1つ**あること。そのトークンだけを置き換え、**他は1文字も変えない**
  - 文字列検索で置換してはいけない。`G線上のアリア` のように教材名の一部に弦名が入る場合に壊れる
  - `汎用` のような弦以外のトークンは対象外。中止して報告する
- 末尾の丸数字（`①`〜`⑩`）は**そのまま引き継ぐ**。採番し直さない
- 拡張子は `.musicxml`。**圧縮しない平文の XML**。UTF-8・BOM なし。改行コードは元と同じ
- 1行目の XML 宣言と `<!DOCTYPE score-partwise ...>` は元のまま写す
- `<score-partwise>` に **`xmlns` を付けない**。既定名前空間を付けると、アプリ側の弦・運指の読み取りが例外も出さずに全滅する

## 7. 触らないもの・足さないもの

元の版に**あるものは変えない。無いものは足さない。**

- 繰り返し: `<barline>`・`<repeat>`・`<ending>`。**解析器は繰り返しを展開してから数えるので、1つ落ちると曲の長さと音符の採番が丸ごと変わる**
- 音楽: 拍子・音価・付点・小節の区切り・連桁・スラー・タイ・連符・アーティキュレーション記号・装飾音（grace）・和音・`<slide>`・`<glissando>`・`<octave-shift>`・`<staff-details>`・`<transpose>`・`<divisions>`・強弱
- テンポ: 元に無ければ**足さない**。あれば値をそのまま引き継ぐ。テンポ記号が無い譜面は解析側で BPM 90 として扱われるので、弦ごとに違う値が入ると同じ組の中で原速がばらつく
- メタデータ: `<work-title>`・`<credit>`・`<credit-words>`・`<identification>`・`<software>`・`<part-name>`・`<instrument-name>`・`score-partwise` の `version` 属性
- 文字指示（`<words>` など）を新たに書き加えない
- 要素の順序と字下げも変えない

`<work-title>`・`<credit-words>`・`<words>` の中に弦名らしき文字が含まれていても、**置き換えてはいけない**。自由文には `_` 区切りのトークンという足場が無く、`G線上のアリア` のような曲名を壊す。見つけたら**報告に「この文字列に弦名がある」と書いて人に回す**。

### 7-1. ただしレイアウトの座標と符尾だけは消す
音の高さが変われば、音符も指番号も弦番号も紙の上の位置が変わり、符尾の向きも変わる。元のまま残すと**数字が音符から離れた位置や重なった位置に描かれ、符尾が全音符で逆向きになる**。実際、人が手で作った `1-3-5-7ポジション移動_{弦}_③` の G線版と E線版は、座標がまったく違い、符尾は58音すべて逆だった。

次は**削除する**。表示用の譜面はアプリ側が組み直すので、消しても実害は無い。

- `<note>`・`<fingering>`・`<string>`・`<accidental>` の `default-x` と `default-y`
- `<measure>` の `width`
- `<print>` の中の `<system-layout>`
- `<stem>`
- `<slur>` と `<tied>` の `default-x`・`default-y`・`bezier-x`・`bezier-y`。音符の縦位置から計算された値なので、残すと弧が音符から外れる。`<dynamics>` など `<direction>` 系の座標は五線の上端が基準で音の高さに連動しないため、消さなくてよい

## 8. 出す前の自己点検

- [ ] 音符と休符の数・並び・音価・付点・タイ・スラー・連符・拍子・小節数が元と同じ
- [ ] 繰り返し・番号かっこの並びが元と同じ
- [ ] テンポ指定の有無と値が元と同じ
- [ ] すべての音の MIDI が 元 + 7 × n
- [ ] すべての音の**音名番号**が 元 + 4 × n（異名同音になっていない）
- [ ] すべての `<fingering>` の値が元と同じ。全角なら半角に直してある
- [ ] 空の `<fingering></fingering>` が残っていない。削除したことを報告に書いた
- [ ] `<pitch>` を持つ音符すべてに `<string>` と `<fingering>` が対でそろい、`<string>` は目標弦ひとつ
- [ ] 休符に `<technical>` が付いていない
- [ ] 弦と運指が**同じ `<technical>` の中**にある
- [ ] 各音のポジション（§1）が元と1音ずつ同じ。未定義になる音の位置も同じ
- [ ] `<accidental>` の有無・種類・`cautionary`/`parentheses` 属性が元と対応している
- [ ] すべての `<key><fifths>` が 元 + n。`<mode>` が元と同じ。新しい fifths が表 4-4a の範囲に入っている
- [ ] いちばん低い音が目標弦の開放弦以上。開放弦と同じ高さの音は指番号 0 だけ
- [ ] いちばん高い音が MIDI 100 以下
- [ ] いちばん高い音が MIDI 88 を超えるなら、`<instrument-name>` が `Violin` であることを確かめた。`Violin` でなければ **§5-20 で中止した**（書き換えてはいけない・§7）
- [ ] §7-1 のレイアウト座標と `<stem>` を消してある
- [ ] テンポ記号とメタデータが元のまま。自由文の中の弦名は置き換えず、報告に書いた
- [ ] ファイル名は弦トークンだけが変わっている
- [ ] `<score-partwise>` に `xmlns` を付けていない（付けると弦と運指の読み取りが例外も出さずに全滅する）
- [ ] 1行目の XML 宣言と `<!DOCTYPE score-partwise ...>` を元のまま写した
- [ ] 圧縮していない平文の XML。UTF-8・BOM なし

**この自己点検は合格の証拠にならない。** 採否は §9 で決まる。

## 9. 検収

### 9-1. 作る・検収する・直す（ここから先は人がやる。作る側には素材フォルダを渡さない）

1〜5 が1本ごとの流れ。6 は登録したあとに欠陥が見つかったとき（登録は §9-2 の9）。7・8 は素材全体の棚卸しで、作り始める前に一度やる。

1. **検収フォルダと出力置き場を作り、検収フォルダには元の版と今回の出力の2本だけを置く。** 突き合わせる相手が要るので、出力1本だけのフォルダでは意味が無い
2. アプリのリポジトリ（`music-app/music-app`）のルートで走らせる。`--base` には**元の版の弦を1文字で**渡す（`G` `D` `A` `E`。`G線` と書くと弾かれる）:

   ```
   python scripts/check_string_variants.py "<検収フォルダ>" --base G --target "<出力の教材名>" --json "<出力置き場>/check_<教材名>_<走らせた回数>.json"
   ```

   **`--target` を必ず渡す。** 出力のファイル名が弦のトークン以外でも変わっていると、元の版と同じ組に入らず**1音も照合されないまま指摘が出ない**。`--target` はその1本が本当に突き合わせられたかを確かめ、されていなければ `FATAL` を出す

   `<走らせた回数>` は 0 から始め、**走らせるたびに 1 ずつ増やす**（渡し方を直して走らせ直したときも増やす）。上書きすると、何を根拠に合格としたかが残らない。**§9-1 の5 の「作り直しは2回まで」とは別の数え方**で、こちらは単なる通し番号。前の結果を残して、何を根拠に合格としたかを追えるようにするため

3. **合格の判定はスクリプトがする。** 画面の最後に出る次の2つだけを見る。
   - `=== 合否に効く指摘 (作る側に返すか元の版へ回すかは指示書 §9-1 の5) ===` の一覧。ここが空で `FATAL` も無ければ合格で、`合否に効く指摘なし: <教材名> は合格` と出る
   - `FATAL` で始まる行。**1行でもあれば無条件に不合格。**照合そのものが成立していない印なので、他の指摘が0でも合格にしない。`FATAL` は専用の節と合否に効く一覧の**両方に出る**。同じ内容が2回見えるが、1件のこと。ただし「指定されたフォルダが無い」「フォルダに .musicxml が1本も無い」の2つだけは、その場で止まるので1行しか出ない

   仕分けの規則（人が目で追う必要は無いが、根拠として）:
   仕分けは3通り。番号で呼ぶ。
   - **仕分け(1) 出力の名前で出た指摘**は、原則すべて合否に効く。ただし `DOCTYPE 宣言が無い` と「調号と合わない高さなのに臨時記号が書かれていない」は、元の版が同じ傷を持っていれば免除する（前者は §6 が「元のまま写す」と決めたもの、後者は §3-1 と §7 の縛りで作る側が直せないもの）
   - **仕分け(2) 元の版の名前で出た指摘のうち、§5 の「入力そのものの不備」（§5-1〜16）に当たるもの、および「ファイルを読めない」「音符が1つも無い」は合否に効く。** `<chord>` がある・`<backup>` がある・運指が無い・元の fifths が範囲の外・`<transpose>` がある、など。これらは**そもそもこの元の版から出力を作ってはいけない**条件なので、出てきた時点で誤り
   - **仕分け(3) 元の版の名前で出たそれ以外の指摘**（全角の運指・BOM・臨時記号の欠落など）は参考情報。元の版にあってよく、出力側で直すか、別途人が直すもの。引き継ぎの免除にしない
   - `欠け:` の行、「基準に指定した◯線がこの系統に無い」の行、冒頭の「弦の名前が `_` 区切りのトークンとして1回だけ現れる形になっていないファイル」の一覧は参考情報
   - `--json` を渡すと、合否に効いた行が `blocking` に残る

   **合格しても、`[組名]` の下に残っている `NG <元の版の名前>:` の行は放置しない。**この行は合否に効く一覧には出ない。画面の `[組名]` の節か、`--json` の `families` の中にある。 参考情報に落ちたものも、元の版そのものの傷であることに変わりはない。**元の版を直す人へ回す。**直さないかぎり、次にその組の別の弦を作るときにまた出る
4. MuseScore で開いて目で確かめる。**指番号と弦番号が音符のそばに正しく置かれているか・符尾の向きと連桁が自然か**（§7-1 の消し忘れは §9-1 の2 で機械が止めるが、消したうえで崩れていないかはここで見る）、**スラーの弧が音符に掛かっているか**、アーティキュレーション記号と装飾音が元のまま残っているか
5. 落ちたとき（手順3の指摘でも、手順4の目視で見つけたものでも）:
   - **手順4 の目視で見つけたもの**（§7-1 の消し残しが招いた崩れ、スラーの弧の外れ、アーティキュレーションの種類ちがい）は画面に行が無い。**何がどう崩れているかを文で書いて作る側へ返す。**作り直しの回数に数える
   - **`FATAL` は文面で行き先が変わる。**
     **検収する人の渡し方の誤り**（直して走らせ直す。作り直しの回数には数えない）
     - 「基準の◯線の版が検収フォルダに入っていない」
     - 「基準の弦と同じなので、比べる相手がいない」
     - 「指定されたフォルダが無い」
     - 「フォルダに .musicxml が1本も無い」

     **作る側の誤り**（§6・§5-23 違反。作り直させる。回数に数える）
     - 「基準の弦の版はフォルダにあるが、同じ組に入らなかった…出力のファイル名が弦のトークン以外でも変わっている」
     - 「弦の名前が `_` 区切りのトークンとして1つに定まらない」

     **元の版の傷**（元の版を直す人へ回す）
     - 「基準の◯線の版を読めなかった」

     **どちらとも決まらない**
     - 「指定したファイルが見つからない」→ まず自分の `--target` の綴りを確かめる。合っているなら、作る側がファイル名ごと取り違えて保存している
     - 「1音も照合されていない。原因を特定できない」→ 検収フォルダの中身を目で確かめる
   - **作る側で直せる指摘**（音の高さ・音名の文字・運指・弦・調号・レイアウトの消し忘れなど）は、該当行をそのまま作る側へ返して作り直させる。作り直しは2回まで。3回目に入る前に人が元の版を見る
   - **元の版の傷に由来する指摘**は作る側では直せない。§5 に番号があるものは中止報告に切り替えて §4-5 の直しへ回す。**§5 に番号が無いもの**（「調号と合わない高さなのに臨時記号が書かれていない」など）は、元の版を直す人に回す。作る側へ戻して往復させない
   - **どちらに回すかは、`NG` に続く教材名で決める。** 出力の名前なら作る側、元の版の名前なら元の版を直す人。「ファイルを読めない」「音符が1つも無い」は出力側でも起きる（圧縮して書き出した、`xmlns` を付けた、XML が壊れている）ので、名前を見ずに元の版の傷と決めつけない
   - **合否に効く指摘の中にも、作る側では直せないものが混じる。**出力の名前で出ていても、次は人の作業に回す。見出しは「作る側へ返す」とは言っていない
     - 調号が範囲の外（§5-12 は元の版の名前で、§5-17 は出力の名前で出る）→ どちらも §4-5 の直し
     - 最高音が MIDI 88 を超えるのに楽器名が `Violin` でない（§5-20）→ **§0-3 の前提作業**。`<instrument-name>` の変更は §7 で禁じているので、作る側では直せない。画面に出る「楽器名を `Violin` にすれば」という助言は、**元の版を直す人あて**であって作る側あてではない
     - 最高音が MIDI 100 を超える（§5-21）→ §9-1 の8 の記録
6. **登録したあとに欠陥が見つかったとき**は、次の順でやる。順番を間違えると §5-22 で止まる。

   - **先に**素材フォルダの該当ファイルを `古い/` へ退避する。**`.musicxml` と `.mscz` の両方。**素材の120本はすべて同名の `.mscz` を持っているので、`.musicxml` だけ動かしても §5-22 で中止する
   - 作り直させる
   - 出てきたものを **§9-1 の2〜4** でもう一度検収する
   - 合格したら素材フォルダへ置き、**差し替えで登録し直す**:

   ```
   REPLACE=1 ONLY="<ファイル名>.musicxml" npx tsx scripts/upload_position_shift.ts
   ```

   Git Bash で走らせる（PowerShell では環境変数の前置きが通らない）。必要な env は §9-2 の9 と同じ。
   **`REPLACE=1` は `ONLY` が必須**（付け忘れると登録済みの全件を差し替えてしまうので、スクリプトが止める）。
   `REPLACE=1` は新しい教材を作らず、既にある教材の Storage の写しを上げ直して解析をやり直す。**教材名が登録時と1文字でも違うと相手が見つからず、`✗ 差し替える相手が見つからない` で止まる**（黙って新しい教材を作ることはない）。教材の id も演奏の履歴も変わらない。**`REPLACE` を付けずに走らせると「既にあるので飛ばす」で何も起きない。**
   - 差し替えると `positions` が空に戻り、解析が終わるまでシートの選択肢から消える。`star` は機械が入れた値（`autoStar` と同じ）のときだけ空に戻り、**人が入れた★は残る**（残したときは画面に `※ 人が入れた★… は残した` と出る）。**`done` を待って §9-2 の10〜12 をやり直す**
   - 退避した `古い/` の中は §5-22 の重複判定には数えない（§0-2 の一覧は素材フォルダの直下だけを見る）
7. **`.mscz` だけがあって `.musicxml` が無い名前**は、素材に11個ある。2種類に分けて扱う。
   - **弦トークンを持つ4個**（`1-3-5ポジション移動_D線_②`・`1-3-5ポジション移動_E線_①`・`3-5-7ポジション移動_A線_①`・`3-5-7ポジション移動_D線_①`）は、人が既に作って書き出し忘れているだけ。**MuseScore から書き出して埋める。**作る側に作らせると §5-22 で中止する。**書き出した1本も §9-1 の2〜4 で検収する。**人の手で作ったものだけが無検査で本番に入るのを防ぐため
   - **`汎用` を含む7個**は弦を決める前のひな形。出力のファイル名は必ず弦トークンを含むので §5-22 には当たらない。**素材フォルダの直下に書き出してはいけない。** `汎用` が教材として登録されると、その系統名のグループの軸に弦以外の値が混ざり、**弦のプルダウンがその系統名ごと消える**。置くなら `古い/` か別のフォルダにする
8. **作れないと確定した弦**（元の版を直しても §5-21 に当たるなど）は、素材フォルダの `作れない弦.md` に「組の名前・作れない弦・理由」を書き残す。**外れるのはその弦1本だけで、組ごと落とさない。**残りの弦はそのまま作って検収する

### 9-2. 組がそろってからやること（`作れない弦.md` に書いた弦を除いて全部できたら）

9. 素材フォルダへ移してから登録する。出力置き場のままでは登録されない。アプリのリポジトリのルートで:

   Git Bash で（PowerShell では環境変数の前置きが通らない）:

   ```
   DRY=1 ONLY="<ファイル名>.musicxml" npx tsx scripts/upload_position_shift.ts
   ONLY="<ファイル名>.musicxml" npx tsx scripts/upload_position_shift.ts
   ```

   1行目は対象と内訳だけ表示する下見。2行目が本番。**下見は本番と同じ `ONLY` を付けて回す。**下見は DB を見ないので、登録済みのものも件数に入る。本番だけが「既にあるので飛ばす」で減る。`ONLY` はカンマ区切りで複数渡せる。
   **`ONLY` を付けずに走らせると、素材フォルダにある未登録の `.musicxml` を全部登録して解析まで投げる。**検収前のものが混じっていると巻き込むので、必ず `ONLY` で名指しする。
   `ONLY` で名指ししたのに「対象: 0 件」で終わるときは、**「対象:」の行より上を見る**。
   - `⚠ 調を読めないため飛ばす` が出ていれば、調号を読めていない。ファイル名は合っている
   - 何も出ていなければ、**名前がファイル名と完全一致していない**（拡張子を落とした、丸数字や全角半角が1文字違う、パスを付けた）

   対象に入ってから飛ばされるのは `= 既にあるので飛ばす`・`✗ 差し替える相手が見つからない`・`✗ アップロード失敗のため取り消し` の3つ。
   必要な env は `DATABASE_URL`・`NEXT_PUBLIC_SUPABASE_URL`・`SUPABASE_SERVICE_ROLE_KEY`・`RELAY_URL`・`RELAY_API_KEY`・`ENABLE_PYTHON_ANALYSIS=true`。最後の1つが無いと解析が投入されず、`analysisStatus` は `queued` のまま動かない。このときは1件ずつ `→ <教材名>: skipped(disabled)` と画面に出るので、見分けはつく。
   同名の教材が既にあれば飛ばす。最後に**教材グループの軸を作り直す**。別の経路で登録したときは、**このスクリプトをもう一度走らせれば軸だけ作り直される**
10. **`analysisStatus` と `buildStatus` が done になってから**、元の版と見比べる。`keyTonic` と `keyMode` は登録の時点で入るが、`positions` と `star` は解析が書くので、待たずに見ると素通りする。期待する値:

   | 見るもの | 期待 |
   |---|---|
   | `keyTonic` | **変わる**。弦の距離ぶん5度ずつ動く。同じなら異常 |
   | `keyMode` | 元と同じ |
   | `positions` | 元と同じ集合 |
   | `autoStar` | 元と同じ。ポジション集合から決まるため |
   | `star` | 人が入れていなければ `autoStar` と同じ値が入る。**null のままなら不合格**（カルテ生成が落ちている）。人が入れた★はその値のまま |

   値は**管理画面の教材一覧**で見る。登録スクリプトが最後に出す状態表は**投入した直後の状態**なので、必ず `queued` のまま出る。確認には使わない。新規登録では「既にあるので飛ばす」ときに表そのものが空になる。

   **元の版が §0-3 より前に登録されていたら、元の版も上げ直す。** 素材フォルダのファイルを直しても、Storage に上がっている写しは `ヴァイオリン` のままで、その教材だけ採点のピッチ上限が E6 に取り残される。上げ直し方は §9-1 の6 と同じ `REPLACE=1 ONLY=…`。**素材フォルダのファイルを直してから**でないと意味が無く、上げ直すと `positions` と `star` が空に戻るので 10〜12 をやり直す

   `star` は人が入れる★、`autoStar` は譜面のタグから毎回計算される★で、別の列。この指示書で作る教材は `star` を入れないので、解析が `autoStar` と同じ値を `star` にも書く。
   **`done` になっていても `positions` が空・`star` が null のままなら不合格。** 解析はカルテ生成の失敗を握りつぶして `done` にするので、中身が空という形で出る。まず §6 の `xmlns` と §5-1〜§5-4 を疑う。
   **ただしこれは低い弦の版でしか食い違いを検出できない。** 弦の指定が落ちた音は「最も低いポジション＝最も高い弦」に解決されるので、E線版は `<string>` が丸ごと無くても同じ値になる。**高い弦の版については、9-1 の手順2の `<string>` 検査が唯一の検出手段**
11. 同じ系統名のものが1つの教材グループに入っていることを確かめる。系統名は**ファイル名の先頭トークンそのまま**なので、`1指のポジション移動` と `2指のポジション移動` は別のグループになるのが正しい
12. **族カードを開いて、練習前シートの「弦」のプルダウンに作った弦が出て、選べることを目で確かめる。** 一覧は系統ごとに1枚のカードなので、一覧を見ても入ったかは分からない。
    確かめるときは**その教材の★以上の★を持つアカウントで開く**。シートは★で変種を先に切り落とし、届かない弦は選択肢ごと消える。
    **シートは番号の軸が①で開く。**弦のプルダウンは「いま選ばれている番号に実在する弦」だけを出すので、③の4弦を完成させても①に無い弦は現れない。確かめたい番号へ先に切り替える。
    出てこないときは、軸を疑う前に **`star` が入っているか**を先に見る。`star` が null の教材はシートの選択肢に載らない。そのうえで DB の `MaterialGroup.axes` を見て、足りなければ**登録済みのファイル名を1つだけ `ONLY` に渡して登録スクリプトを走らせる**（§9-2 の9）。登録は空振りし、軸だけが作り直される
13. **どの弦でも、7ポジション以上を含む場合は弾けるかを人が判断する。** ポジション番号が同じでも、弦によって別の技術になる。
    - **G線・D線の高ポジション**は肘を深く回し、楽器の肩を越える
    - **E線・A線の高ポジション**は指板の端に出る。E線の第10ポジションは本体の上になる。`4指のポジション移動` のような初級の題名でも、E線版は D♯7（MIDI 99・第10ポジション）まで上がる
    - **§5-21 の MIDI 100 は採点のピッチ検出の上限であって、弾けるかどうかの線ではない。**通ったから弾けるという意味にはならない

## 10. 報告の形

MusicXML と別に必ず出す。

- 元ファイル名 → 新ファイル名
- 元の弦 → 目標弦 ・ n の値
- `fifths` と `<mode>`: 元 → 新
- 最低音・最高音: 元 → 新（MIDI と音名）。**最高音が 88 を超えるなら、そのことと `<instrument-name>` の値を明記する**
- 出てくるポジションの集合: 元 → 新（同じであること）
- 空の `<fingering>` を削除したなら、その数
- `<work-title>`・`<credit-words>`・`<words>` の中に弦名らしき文字があったなら、その文字列（置き換えずに報告する・§7）
- §8 の点検結果
- 中止した場合: §5 のどの番号か、どうすれば作れるようになるか。
  **場所を添える条件**: 2・3・4・5・7・8・9・10・11・13・14・15・16・18・19・20・21、および 6 のうち「`<fifths>` が2種類以上」の場合（「2種類以上」の条件は、2つ目が現れた場所を書く）
  **場所を持たない条件**: 1（`<part>` の数）・6 のうち「`<key>` が無い」場合・12・17（どちらも調号の話）・22・23（運用の話）

## 11. 分かっている限界

- **軸は保存された配列なので、教材を足しただけでは選択肢が増えない。** 登録スクリプトの最後で作り直される。別の経路で登録したときは、**登録済みのファイル名を1つだけ `ONLY` に渡して走らせる**。登録は空振りし、軸の作り直しだけが走る。`ONLY` を付けずに走らせると未登録のものを全部登録してしまう。ただし `DRY=1` は軸の作り直しの手前で終わるので、下見の行では直らない（§9-2 の12 で必ず目視する）
- **高い弦の版は、弦の指定が落ちても登録後の自動判定が一致してしまう**（§9-2 の10）
- **教材名の数字とポジションが元から食い違う系統名がある。** 例: `3-4-5-6-7-8-9-10ポジション移動` は、この数え方だと 3〜11 ポジションになる。指示書は名前を転写するだけで数字を作り直さない
- 同じポジション番号でも、弦によって弾きやすさは違う（§9-2 の13）
- 照合スクリプトの「音符の数」は、解析器の note_index の数え方とは別（解析器は重音と装飾音を数に入れない）
- 全角の運指は Python の `int()` が読めてしまうので実害は出ないが、表記は半角にそろえる
- **機械では検査されないもの**: 要素の**数は同じだが種類が入れ替わった**もの（強弱の記号を別の種類に変えた、スタッカートをアクセントに変えた、など。数が変われば止まる。スラーの掛かる範囲は音符ごとに見ているので検出される）、§5-22 の同名の重複（検収フォルダしか見ないので原理的に分からない）、`<barline>` のうち `<repeat>` と `<ending>` 以外（`<bar-style>` など）、`<work-title>` や `<credit>` などのメタデータを変えていないか（`<instrument-name>` だけは機械が見る）、`<words>` の弦名を置換したか、要素の順序・字下げ・改行の細部。これらは §9-1 の4 で人が見る
- 照合スクリプトが見るもの: `<beam>`・`<dynamics>`・`<words>`・`<octave-shift>`・`<glissando>`・`<slide>`・`<staff-details>`・`<wedge>`・`<metronome>`・`<tuplet>`・`<grace>`・`<chord>`・`<articulations>`・`<ornaments>`・`<technical>`・`<notations>`・`<tie>`・`<tied>`・`<slur>` の**数**・音部記号・`<divisions>`・1行目の XML 宣言の有無・**§7-1 の消し忘れ（座標・`<measure>` の width・`<system-layout>`・`<stem>`・スラーとタイの制御点）**・音の高さ・音名の文字（オクターブ込み）・運指の値と表記と個数・空の `<fingering>`・弦・弦と運指が同じ `<technical>` にあるか・ポジション・調号と mode と使用可能範囲・臨時記号の有無と種類と `cautionary`/`parentheses`・alter が ±2 の外・**調号と合わない高さなのに臨時記号が無い音**・音価と付点・タイ（`<tie>` と `<tied>`）・スラーの掛かり・連符・拍子・繰り返し・テンポ・小節数・装飾音の有無・和音・`<part>` の数・`<staves>`/`<staff>`/`<voice>`/`<backup>`・`<transpose>`・`<instrument-name>` を書き換えていないか・開放弦より低い音・開放弦と同じ高さなのに指1以上・指0なのに開放弦の高さでない・休符に `<string>` や `<technical>`・1つの音符に `<string>` が2種類・採点できる音域の上限・BOM・名前空間・DOCTYPE・圧縮されていないか
- そのうち **「調号と合わない高さなのに臨時記号が無い」は、この指示書では直せない**。§3-1 と §7 が「元のまま引き継ぐ・足さない」と定めているため。元の版の傷として人に回す（§9-1 の5）
