## 1. 目的・スコープ
1つの曲を、**難易度別**（初/中/上）と**パート分け**で扱える仕組みの**設計を確定**する。両者は**非対称**：難易度＝別スコア（変種）、パート＝グループ共通の分割構造（難易度非依存）。UIとコンテンツ制作は後段。

**スコープ内**：データモデル・軸の抽象・変種の選択/状態・達成の単位・推薦の重複排除・アップロード/管理・移行・マイグレーション方針。
**スコープ外**：実際のパート/難易度スコアの制作、詳細なUIビジュアル。

## 3. 中核モデル（★難易度とパートは“非対称”）

> 確定：**難易度＝別スコア（変種軸）／パート＝グループ共通の分割構造**。パートは「別スコア」ではなく、各難易度スコア内の分割で、分割の定義（どこで切るか）はグループに一度だけ持つ。

```
MaterialGroup（論理的な「1曲」＝一覧の単位・カバー1つ）
  ├─ parts: [P1, P2, … Pn]   … ★分割セット（どこで・いくつに分けるか）を“1回だけ”定義。
  │                             個数nは曲ごとに可変。難易度では変わらない
  ├─ Score(初級)  … 同じ分割セットを、このアレンジの小節に位置づけ
  ├─ Score(中級)  … 同上（別アレンジなので小節位置は違い得るが、分割セットは同じ）
  └─ Score(上級)  … 同上
```

- **難易度＝変種軸**：各難易度は**別Score（別アレンジ・別MusicXML）**として用意する（これは変わらない）
- **パート＝1つの共有分割**：「どこで・いくつに分けるか」は曲の構造で**難易度共通**、ただし**個数は曲ごとに可変**。だから**グループに1回だけ `parts` を定義**する。**難易度ごとに分割を作り直さない**
- **難易度で違うのは“位置”だけ**：同じパートが「このアレンジの何小節か」という**位置**のみアレンジ固有（分割の作り直しではない）。難易度アレンジが**同じ小節割りなら位置も一致**し、実質1回定義で済む
- **パートの練習＝区間**：あるパートを練習する＝そのスコアでの該当範囲を**既存の区間録音（`rangeFromNote`/`rangeToNote`）**で弾く。＝部分練習・部分採点の既存機構を再利用
- 帰結：**パートは独立エンティティを増やさない**（Scoreは難易度分だけ）。難易度×パートの掛け算でスコアを量産しない

## 4. データモデル設計（範囲ベース・partId付与）
**パート＝「◯小節〜◯小節」の範囲**。区切りを“点”では持たず、**範囲**で持つ。難易度共通（＝難易度アレンジは同じ小節割り前提。第12節Q1）。

| モデル | 追加/変更 | 役割 | 種別 |
|---|---|---|---|
| `MaterialGroup` | `parts Json?`＝`[{ id, name, startMeasure, endMeasure, order }]`（**可変長**） | **分割の正準定義**（範囲）。曲ごとに個数可変・難易度非依存 | 加算・null許容 |
| `Performance` | `partId String?` を追加 | **この区間録音がどのパートか**を明示（セレクタで各パートの点数を出すため） | 加算・null許容 |
| `Score.difficulty` | 既存のまま（変種軸） | 難易度＝別スコア | 変更なし |

- **正準は `MaterialGroup.parts`**（範囲リスト）。難易度で作り直さない。個数は曲ごとに可変
- **`Score.part` は作らない**（パートは別スコアではない）。難易度だけが変種軸
- **`Score.sections`（既存）は使わない方針**：パートはグループの範囲を各Scoreの音符に解決するため、Score個別の区切り保持は不要（前提：難易度で小節番号が一致）
- **マイグレーション**：`MaterialGroup.parts` / `Performance.partId` は加算・null許容。パート未定義の曲・通し録音は null で無害

### 4.1 小節範囲 → 音符範囲の解決（既存機構に接続）
- 区間録音の範囲は**音符インデックス**（`rangeFromNote`/`rangeToNote`）。各音符は `measure_number` を持つ
- パート練習開始時：`parts[partId]` の `startMeasure/endMeasure` を、そのScoreの解析音符から**音符範囲に解決**（先頭小節の最初の音符〜末尾小節の最後の音符）→ `rangeFromNote/rangeToNote` に設定
- → **既存の区間録音＋部分採点をそのまま利用**。区間録音は公式スコア非算入（＝曲達成に影響しない）も現行どおり

## 4.2 パート＝“ミニ曲”として第一級（Tetsuo確定 2026-07-26）
各パートは、**自分の詳細画面と振り返り画面を持つ**。通し（曲全体）とは別立て。

- **譜面表示＝そのパートの小節だけ**：パートを選ぶと譜面を該当小節範囲に限定表示（OSMD `drawFromMeasureNumber`/`drawUpToMeasureNumber` で実現可）
- **採点＝その小節に限定**：小節範囲→音符範囲に解決し `rangeFromNote/rangeToNote` で部分採点。点数（音程/リズム）はそのパート範囲のみ
- **パートの振り返り＝そのパート専用の推移**：先日の「上達のようす」グラフを **`partId` で絞って再利用**（＝そのパートの録音だけの推移）。**おすすめ教材/学びポイントは非表示・点数は表示**
- **推移グラフは2系統**：通し（曲全体・区間除外）／各パート（partId絞り）。混ざらない
- **曲達成には非算入**（区間録音扱い・現行踏襲）。パートは達成判定に影響せず、練習と推移の可視化のみ
- **セレクタに自己ベスト**：曲/難易度/パートを選ぶUIで、**一度弾いたら各項目の右に自己ベストを小さく表示**（`Performance.partId` 単位で集計）。難易度＝通し自己ベスト、パート＝部分自己ベスト

## 5. 軸の適用ルール（materialVariant.ts）
- **変種軸＝難易度のみ**（曲・エチュード）／基礎練は `articulation × key`（従来通り）。→ `PARTS` は**変種軸ではない**ので `DIFFICULTIES`/`ARTICULATIONS` の仲間に加えない
- **パートは「グループのメタ構造」**として別に扱う（`MaterialGroup.parts` ＋ 各Scoreの `sections`）。「どの難易度スコアでも同じパート集合が使える」ことを保証

## 6. 選択・状態
- **難易度の選択＝どのScoreを開くか**（変種選択）。グループ → 難易度選択 → そのScore詳細
- **パートの選択＝そのScore内のどの範囲を練習するか**（区間の指定）。Score詳細で「パート」を選ぶと `sections[partId]` の範囲で録音/練習（既存の区間録音UIに“名前付きプリセット”を足す形）
- 欠けている難易度は選択UIで非活性。パートは全難易度で同じ集合（グループ定義）

## 7. 達成/マスター・練習データの単位（engine不変）
- **曲の達成/マスターの原子単位＝Score（難易度）**：今のまま（`UserScoreAchievement` 等）。**判定エンジン（Python）不変**
- **パート練習は区間録音**＝既存ルールで**曲スコアには非算入**（`rangeFromNote != null` を除外）。つまりパートは「練習の足場」で、曲の達成は**通し演奏**で決まる（現行踏襲）
- **任意強化（決めどころ）**：パート単位の“できた”を可視化したい場合、区間録音の結果をパート別に集計（新テーブル不要・読み取り集計）。曲達成の定義は変えない
- **グループ級ロールアップ**：一覧で「この曲」を1枚に集約表示。難易度別の達成状態はカード内で示す（導出・読み取り時）

## 8. 重複排除（実態＝軽いガードのみ・大がかりな仕組み不要）
実コード確認の結論：
- **マイライブラリー（一覧）**：既に **MaterialGroup 単位＝1曲1枚**（[piecesList](../app/[userId]/practice/pieces/page.tsx) が `materialGroup.findMany`）。**重複しない**
- **「次の曲にチャレンジ」**：個別Scoreを**現在★で絞る**（[page.tsx:378](../app/[userId]/page.tsx#L378)）。難易度別は★が違うため**通常1つしか一致しない**。同★が偶然重なるエッジのみ group 未考慮で重複し得る
- **毎日の基礎練/弱点推薦**：曲は出さない（教材）。ただし**エチュードの難易度別**は推薦上位に同一グループ違いが並び得る
- **対応（軽い）**：「次の曲」クエリと教材推薦に **`groupId` で 1グループ1つのガード**を足すだけ（大がかりな重複排除システムは不要）

### 追加確定（2ラウンド目）
- **A 教材の作り方：案1（アップロード時入力）**。`uploadScore` は既に `groupId`＋`difficulty` 対応。それに加えて**曲アップロード時に `parts` を任意個 動的入力**（名前・開始小節・終了小節の行を増やせる）。parts はグループに保存
- **B 開いたときの既定難易度**：**未演奏なら現在★に最も近い難易度／演奏済みなら最後に弾いた難易度**
- **C 曲の達成**：曲全体の単一達成は作らず**難易度ごとに達成バッジ**
- **D パートの対象**：**曲（Score）だけ**（エチュード等は対象外）
- **E スコア保持**：**(難易度×パート) と (難易度×通し) を別々に自己ベスト保持**
- **F difficulty と star**：役割分担で**両方保持**（difficulty＝変種スイッチ見出し／star＝グレード・★昇格）
- **G パート＝ミニ曲**：各パートに**詳細＋振り返り**。振り返りは**そのパート専用の推移**（partId絞り）・おすすめ非表示・点数表示。推移グラフは通し／パートの2系統
- **H OSMD部分表示：フィージビリティOK**（`drawFromMeasureNumber`/`drawUpToMeasureNumber` で小節範囲描画）

### 追加確定（3ラウンド目）
- **パート編集ライフサイクル**：編集/削除/並べ替え可。**part id は固定ID**（配列indexでない）で `Performance.partId` が生き続ける。削除は**論理削除**（過去録音は残しセレクタから隠す）
- **パート録音の解析**：pitch/timing は**算出する**（推移に必要）。抑制は**おすすめ教材/学びポイント表示だけ**
- **通しとパートの境界**：曲達成＝**通し3回のみ**（パートは代替不可）。パート独自の達成/祝いは**作らない**
- **セレクタ構造**：**難易度を選ぶ→その中で [通し / Part1…Pn] を選ぶ**（各右に自己ベスト）。通しもパートも同じ「詳細＋振り返り」を持つ
- **difficulty 必須化**：`Score.difficulty` は**必須**（null を無くす）。既存 null は set-all-beginner でBEGINNERへ。**degrade は parts=null（通しのみ）だけ**
- **現在難易度の決定**：ユーザー `currentStar` に最も近い★の変種
- **パートの祝い（celebration）**：**今回やらない**（振り返りに自己ベスト表示のみ）
- **区間ループ/お手本のパート自動連携：含める**。パート選択で、既存の区間ループ（お手本音源のループ再生）とテンポガイドを**そのパートの範囲に自動セット**（範囲は算出済みで低コスト）。＝パートのコアは 表示/録音/採点/推移＋**お手本ループ**

### 追加確定（4ラウンド目）
- **パートは「任意のスポット」許容**：曲全体を覆う必要なし・部分/難所拾いOK・**重なり/隙間許容**（＝完全分割ではない）
- **パート入力は案b（アップロード時に入力）**：アップ者が元譜面の小節を把握している前提で、アップロード時に parts を入力
- **パートは独自タグを持たない**：パートは範囲のみ。弱点は「その範囲の実音符」を診断が拾う（タグ非依存）
- **お気に入りは group 単位へ**（曲でお気に入り）／**目標曲は group 紐付け・表示は現在難易度に解決**
- **タグ付けは自動**：解析パイプライン（`musicxml_skill_extractor.py`→`analyze_musicxml.py`）が MusicXML から技術タグ・ポジションを**自動抽出しScoreへ付与**。各難易度は別MusicXMLで**独立に自動タグ付け**＝手作業ゼロ（authoring負荷は非該当）

## 14. 整合性（既存サービス設計との）
- **原則**：タグ・技術・調・ポジション・達成・演奏履歴・お気に入り・スキルタスク・診断 は**すべて Score/PracticeItem（変種）単位**。group単位は 一覧・カバー・タイトル。→ 難易度変種＝別Scoreなので**すべて変種ごとに正しく整合**（初級/上級で技術・ポジ・調が違ってよい）
- **タグ＝自動付与**（各変種の解析で独立に）→ 変種モデルと好相性・負荷ゼロ
- **分析**：Score単位。パート＝既存の部分採点（区間録音）に相乗り。各難易度は独立解析
- **parts のみ group 単位**（難易度共通ゆえ）＝唯一の例外・理由明確
- **要変更（整合のため）**：①お気に入りを group 単位 ②目標曲を group 紐付け（現在難易度に解決）
- **軽微**：`group.title` を表示の正とし `score.title` は内部用

## 付録：設計原則
- **難易度＝別スコア（変種軸）／パート＝グループ共通の分割**（非対称）。パートで独立エンティティを増やさない
- **パート練習は既存の区間録音（rangeFromNote/To）を再利用**。曲の達成は通し演奏で判定（現行不変）
- **判定エンジン（Python）・祝い設計に波及させない**（達成の原子＝Scoreのまま）
- **加算・null許容のみ**でスキーマ拡張（パート未定義の曲は分割なしで無害に継続）
- **重複排除はグループ単位**で（推薦・一覧）
