# 画面幅の基準

2026-08-27 確定。以後、画面幅に関わる指定はこの文書に従う。

## なぜ必要か

この repo には画面幅の指定が 15 個あり、境界値が **9 種類** ばらばらだった。
380 / 400 / 430 / 440 / 500 / 600 / 760 / 768 / 900。

同じことを別の数字でやっていた。`practice` は 400px で 1 列、`home` は 430px で
1 列。理由は無く、書いた人が違うだけだった。

一方で **Tailwind v4 が入っており、既定の境界値が最初から存在していた**。
使用箇所は 0 だった。基準が無かったのではなく、あるのに使わず、隣で別のものを
作っていた。

## 原則

### 1. まず、境界値を使わずに収める

「◯px 以下ならこうする」ではなく「入らなくなったら折り返す」で書く。
これで解ける場合は境界値を作らない。

| やりたいこと | 書き方 |
|---|---|
| 並びきらなければ次の行へ | `flex-wrap: wrap` |
| 入るだけ列を作る | `grid-template-columns: repeat(auto-fit, minmax(◯px, 1fr))` |
| 上限つきの幅 | `width: min(◯px, 100%)` / `max-width: 100%` |
| 画面に応じた余白 | `padding: clamp(最小, ◯vw, 最大)` |

理由は 3 つ。

**端末が増え続ける。** 折りたたみが普及すれば境界値を足すことになる。伸縮なら
足す必要がない。

**境界の直前がいちばん窮屈になる。** 600px 用の組み方を 601px の画面が使うため。

**値が増えるほど誰も基準が分からなくなる。** 実際にそうなっていた。

### 2. どうしても切り替えが要るときだけ、Tailwind の値を使う

「詰まってきたから緩める」ではなく **見せ方そのものを変える** ときだけ。
例: サイドバーを隠す / 常に出す。1 カラム / 2 カラム。

使ってよい値は Tailwind v4 の既定値のみ。新しい値を発明しない。

| 名前 | min-width | max-width で書くとき |
|---|---|---|
| sm | 640px | 639.98px |
| md | 768px | 767.98px |
| lg | 1024px | 1023.98px |
| xl | 1280px | 1279.98px |
| 2xl | 1536px | 1535.98px |

`.tsx` で Tailwind クラスを使う場合は `sm:` `md:` `lg:` をそのまま使う。
CSS モジュールでは上の数値を直接書き、コメントに対応する名前を添える。

```css
@media (max-width: 639.98px) {  /* Tailwind sm 未満 */
```

### 3. 部品の中では、入れ物の幅を見る

画面の幅ではなく、その部品が置かれた場所の幅で決める。同じ部品を狭い所にも
広い所にも置けるようになる。既に onboarding / homeBlocks / lessons で使っている。

```css
.frame { container-type: inline-size; }
@container (min-width: 400px) { ... }
```

## 置き換えの手順

境界値を伸縮に置き換えるときは、**必ず前後の列数を実測して比べる**。
値を目分量で決めると端末によって列数が変わる。

2026-08-27 の置き換えでは、`minmax()` の値を 320 / 360 / 375 / 390 / 414 / 430 /
500 / 640 / 768 / 1024px の 10 通りで実測し、従来と同じ列数になる値を選んでいる
(keyGrid は 115px だと 414px 端末だけ 1 列少なくなったため 110px に修正した)。

### 残っている 1 個

`WelcomeSlides.module.css` の `@media (max-width: 380px)`。
文字の大きさ・絵の大きさ・余白など 12 項目をまとめて縮めている。

これは「切り替え」ではなく「縮める」ので、原則どおりなら `clamp()` にすべき。
ただし 12 項目すべての基準値と縮小値を突き合わせないと、380px 以外の端末でも
見た目が変わる。オンボーディングの最初の画面であり、崩すと影響が大きいため、
この画面を触るときに実測しながら移行する。
