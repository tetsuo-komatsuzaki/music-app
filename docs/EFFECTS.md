# 演出の台帳と写経の作業規約

## 作業規約 (2026-08-20 Tetsuo指示 ・ 必ず実施)
1. **仕様書を開いてから書く。** 記憶で書かない。確定モック・要件定義 (演出要件v1.1 /
   配色案1 / ナビ要件) を該当箇所ごとに開き、値を見ながら写す
2. **演出は写経と同時。** 「あとでまとめて」に切り出さない。data-anim 宣言は
   その画面のDOMを書くときに一緒に付ける
3. **写経の完了定義 = 次の5点が全部そろって完了**
   - DOM一致 (モックの構造どおり)
   - CSS一致 (computed style の突き合わせ)
   - data-anim 宣言 (block/ring/bar/count) と遅延描画ブロックの発火確認
   - この台帳の全行チェック
   - **docs/EFFECTS-CODE.md の「ページ作成チェック」7項目** (トップページと同じ演出が
     全ページ統一で掛かるための義務。DSクラスと data-anim 宣言で組む)
4. 実施済み画面にも、規約変更のたびに再チェックをかける
5. **開いた証拠を残す (2026-08-20 追加・要約起因の再発防止)**
   - 仕様のソースにしてよいのは次の3つだけ: (a) モック生成コードの原本ファイル
     (b) 確定モックのHTML/アーティファクト (c) 要件定義文書。
     **セッション要約・記憶・過去に自分が書いたコードを仕様のソースにすることを禁止**
   - 写経の完了報告には「開いた原本のパス」と「**値の対照表** (原本の値 → 実装の値。
     ms・色・px・セレクタ)」を必ず載せる。対照表が書けない = 開いていない、として書き始めない
   - **コンテキスト圧縮 (要約) を跨いだら、再開の最初に該当原本を開き直す。**
     要約は「何が落ちたか分からない」性質のもので、仕様ソースには決してならない
6. **最初から仕様書のまま実装する (2026-08-21 Tetsuo指示)**
   「だいたい作って実測で直す」往復をしない。**原本の値 (px/ms/色/構造) を最初から
   そのまま書き写して一発で作る。** 実測 (パリティ/スクリーンショット) は
   写経が終わったあとの**検証にだけ**使う。実装の代わりにしない
   - **手順 (シーケンス) も値と同格の仕様。** 原本の reset→noTx→リフロー→rAF→発火 の
     ような段取りを、省略・並び替え・別機構への置き換えしない。移植は原本の関数構造と
     1対1で写し、完了報告に手順の対応表を載せる
     (根拠: noTx とリフローを省いて時差とリング描画が消えた事故 2026-08-21)
6.5 **計測点の出典主義 (2026-08-21 Tetsuo指示)**
   検証の計測点には必ず仕様の出典を紐づける。**出典の無い計測点は「仕様未定義」として
   docs/SPEC-GAPS.md に記録する** (削除も黙認もしない)。定義漏れを一覧化し、
   Tetsuoの裁定で仕様に昇格 or 廃止を決める
7. **完了時の規約自己点検 (2026-08-21 Tetsuo指示)**
   作業を完成させたら、完了report の前に**この規約1〜8を1条ずつ自己点検**する。
   規約どおりになっていない部分が見つかったら、**報告せずにまずその部分をやり直し**、
   やり直し済みの状態で報告する。報告には点検結果を条番号つきで載せる
8. **モックの修正指示 = 仕様書の修正 (2026-08-20 Tetsuo指示)**
   確定モックを修正する指示を受けたら、**必ず仕様書 (docs/MOTION-SPEC.md ・ この台帳 ・
   該当の要件書) も同時に更新する**。仕様書は画面制作の設計書であり、
   そこが直っていないと以後の画面が古い仕様で作られてしまう。完了報告に反映先を明記する

## 出現の大原則 (2026-08-20 Tetsuo指示で明文化 ・ 要件v1.2)
1. **すべてのカードが「起き上がり」の対象。** いま練習している曲カード・おすすめ曲カード・
   独自スタイルのカード (data-anim="block") も例外なく塊として起き上がる
2. **カードが起き上がった後、中の各項目 (行・文章) が順番に起き上がる** (先行170ms→95ms刻み)。
   ラベル (.lab) だけは枠と一緒に出る
3. 項目の中の ★・チェック・ピル・バー・数字は、**自分の項目が出た時刻を起点**に灯る
4. 今後の画面作成はすべてこの前提で書く。写経チェックでもこの3点を画面ごとに確認する

## data-anim の宣言ルール (演出要件v1.1)
- `data-anim="block"` … DSクラス以外の独自カードを塊として出す
- `data-anim="ring"` + style `--p: N%` … リング描画
- `data-anim="bar"` + style `--w: N%` (中身は `<i>`) … バーの伸び
- `data-anim="count"` … 数字のカウントアップ (子タグを含めない)
- `data-anim="chart"` … 折れ線SVGの描画演出 (本物イラストと区別する明示宣言。モックの .appfig 除外に相当)

## v4 での申告事項 (2026-08-20)
- 入れ子の塊 (カードの中のカード) は「項目」として出す。モックは内側にも枠時間を配るが、
  アプリの実DOMに深い入れ子がほぼ無いため簡素化 (発生したら写経時に個別確認)
- ds.stars の★分割は初回描画のみ。Reactが再描画すると素の表示に戻る (静的表示が前提)
